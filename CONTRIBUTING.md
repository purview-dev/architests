# Contributing

Thanks for taking an interest. This repository ships `Purview.Architecture.Testing` and the
`architests` tool, and applies every rule it ships to itself.

`AGENTS.md` is the detailed engineering guide — layout, conventions and the non-negotiables. This
file is the short version for a human contributor.

## Getting set up

```bash
dotnet tool restore
just restore
just build
just test
```

You need the .NET SDK pinned in `global.json`. [`just`](https://github.com/casey/just) runs the
supported workflows; `just --list` shows them all.

## Before you open a pull request

```bash
just lint-check      # dotnet csharpier check .
just test
architests validate
architests api check
```

`just pipeline-pr` runs the CI-equivalent pipeline locally, which is the surest way to avoid a
surprise.

## The things that will get a pull request sent back

These are not style preferences; they are what keeps the package honest.

- **A new rule must be evaluable from an in-memory fixture.** The evaluator takes a graph, not a
  directory, so every rule is testable as a small fixture rather than a repository on disk.
- **A new rule must be enabled in this repository's own policy in the same commit.** A rule that
  cannot pass here is not ready to ship.
- **A new rule must be added to `ArchitectureRules.Catalogue`, both READMEs, `docs/` and the
  skills.** `RuleDocumentationTests` fails on drift, so this is enforced rather than hoped for.
- **Every rule needs a happy *and* an unhappy path test.** A test asserting a rule reports nothing
  cannot distinguish a rule that correctly ignored something from a rule that has stopped working.
  The paired scenarios live in `src/tests/ArchitectureTesting.AcceptanceTests`, written with
  [BDTest](https://github.com/thomhurst/BDTest) so they read as prose.
- **Never read an assembly by loading it.** Metadata only. See the design commitments in
  `SECURITY.md`.
- **Tests must pass identically on Windows, Linux and macOS.** Build paths with `Path.Combine`;
  keep fixtures under the temp directory.

## Commits

Conventional Commits, enforced by commitlint through a lefthook `commit-msg` hook. `build:`,
`chore:`, `docs:`, `feat:`, `fix:`, `refactor:`, `test:` and the rest of the standard set.

## Versioning and release

`package.json` holds the authoritative version. Release is automatic on push to `main`. Please do
not create tags or publish packages by hand.

Public API changes are ordinary reviewed changes: deliberate, in the same commit, with
`.config/api-surface.json` regenerated by `architests api capture` and explained in the pull
request description.

## Reporting a security issue

Not here — see [SECURITY.md](SECURITY.md).
